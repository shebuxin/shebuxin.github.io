## Cloudflare 账户与控制台操作

用户已经在 Chrome 登录 Cloudflare，并通过网页连接 GitHub account 和本仓库，建立了独立的网站部署。首轮沿用这套 Git 集成与控制台配置方式。进入部署工作时，先检查项目类型：Pages 使用 Pages Functions；若项目实际为 Workers，则使用 Worker 路由承载相同接口，不要求迁移现有网站。[Functions 部署文档](https://developers.cloudflare.com/pages/functions/get-started/)

### 三种访问方式

| 访问方式 | 用途 | 第一版安排 |
| --- | --- | --- |
| Chrome 中的 Cloudflare 登录会话 | 查看项目、配置 Secrets 和数据库绑定、检查部署和日志 | 沿用用户的手动登录；后续部署任务中可用浏览器工具协助操作 |
| 已有 Cloudflare 与 GitHub 集成 | 从指定仓库与分支构建、发布网页和 Functions | 先检查现有授权是否覆盖本仓库，再复用；不重新连接已正常工作的集成 |
| Wrangler 登录或 Cloudflare API token | 批量导入私有课程 SQL、CLI 资源管理 | 代码部署沿用 Git；大量 D1 数据导入使用一次性浏览器登录，目标确认后执行，无需提前提供全账户 token |

Chrome 登录会话用于网页操作，不自动等于命令行或 API 授权。Wrangler 的远程账户登录有自己的授权流程；只有选择这条路线时才需要接入。现有 Git 集成可以直接部署 Functions，无需为每次发布另外创建 Cloudflare API token。[Wrangler 授权说明](https://developers.cloudflare.com/changelog/post/2026-08-04-wrangler-login-device-flow/)、[Git 集成说明](https://developers.cloudflare.com/pages/configuration/git-integration/)

Cloudflare 账户权限、模型提供商 API 凭证、学生课程邀请码分别用于管理云资源、支付模型调用和控制课程访问。学生使用聊天时不需要登录教师的 Cloudflare 账户，也不需要提供自己的模型 API key。

### 进入控制台后需要核实的项目

- [ ] 找到正确的 Cloudflare account 和网站项目，记录项目名、类型、生产网址、生产分支和最近成功部署。
- [ ] 核对 GitHub repository、项目根目录、现有 Jekyll 构建命令、构建输出目录及 Preview 分支设置。预计输出为 `_site`，以控制台实际配置为准。
- [ ] 核对当前账户角色是否能编辑项目配置、设置 Secrets、创建 D1 并管理绑定；若为团队账户，只处理缺少的具体权限。
- [ ] 确认 Functions／Worker 能力与套餐额度，记录聊天 API 使用的固定生产地址。新增付费套餐是否需要，按试用测量结果与预算决定。

这些核查安排在云端部署准备时进行，不阻塞本地语料整理、界面开发和测试。

## 第一版的学生体验

学生打开 ECE 685 页面，点击“问 AI / Ask AI”，进入聊天侧栏。试用访问使用课程邀请码交换服务端签发的会话凭证，模型调用由平台提供。

侧栏显示当前讨论位置，例如“L05 · 课件第 12 页”。学生可以选中文字后请求解释，也可以直接输入问题。发送前保存当时的位置，之后翻页不会改变已经发送的问题背景。当前页面没有明确指代对象时，AI 先请求学生指定内容。

回答默认采用问题所用的语言，先解释直观含义，再按需要展开变量、单位、假设、推导或例子。学生可以继续问“为什么”“再简单一点”“举个例子”。引用显示为“L05 · 第 12 页”或“L13 · 概念说明”，点击后打开准确位置。

第一版支持课程概念、课件、公式和已发布教学代码的解释。学生自行修改的代码，只有主动附到问题中才发送。模型自动执行代码、自动修改课程、长期学生画像、自动批改和跨设备聊天历史留到后续阶段。

## 技术方案与数据约定

网页继续由 GitHub Pages 和 Cloudflare 提供；聊天运行时采用 Cloudflare Pages Functions／Worker 的原生 JavaScript 模块和 Web API。Python 用于课程导出和知识库同步，在本地运行。Cloudflare 前端调用同域聊天 API；GitHub Pages 前端调用其完整生产地址，后端校验允许的来源和会话凭证。

服务将当前位置对应的材料直接放入上下文，并使用 Responses API 的 File Search 检索整个 ECE 685 已发布知识库。托管 File Search 提供文件检索和文件引用；逐页课程定位由我们维护的来源映射完成。[File Search 官方文档](https://developers.openai.com/api/docs/guides/tools-file-search)

```text
课程材料 → 导出与质量检查 → 版本化文档、来源映射与托管索引
                                      ↓
GitHub Pages 或 Cloudflare 页面 → Cloudflare 聊天 API → 模型回答与引用
          ↑                           ↓                  ↓
          └────────────────────── 返回页面侧栏 ───────────┘
                            D1 短期会话与调用计数
```

### 课程文档与来源

导出脚本生成 `documents.jsonl`、用于上传的 Markdown 文档、`manifest.json` 和 `quality-report.json`，默认放在 `tmp/ece685-chat/`，实现时将该生成目录加入 `.gitignore`。第一版将当前材料文本与来源映射写入 D1 的课程文档和版本表，托管 File Search 保存检索索引；Cloudflare 接口按版本读取当前页的材料，避免依赖服务器本地磁盘。

每个文档包含 `doc_id`、`course_id`、`kind`、`language`、`text`、来源哈希和语料版本。讲义/网页/代码使用 `lecture_id`、课件页码或网页 section 与公开出处 URL。课程参考资料使用 `reference_id`、`source_type`、`source_role`、版次/年份、章节、印刷页与 PDF 实际页；可以关联多个讲次，单个 `lecture_id` 为 null。私有参考出处的 URL 为 null，用书目与位置显示引用，不伪造公开教材链接。没有明确页标签的 PDF 不猜测印刷页号。后续 D1 文档表与引用接口采用这套扩展字段。

教材选择使用独立的 `course_material_selection` 文档，记录用户选择与日期，PDF 页及印刷页均为 null；不得引用成教材或 syllabus 原文。合并 manifest 标识 `platform_textbook_edition: 6` 和 `textbook_selection_doc_id`。服务读取这份课程级配置并随请求传入，避免仅检索到 syllabus 的旧书目就给出错误的平台版次。选择仅覆盖平台教材依据，其他政策仍按当前 syllabus。`compatible_for_assigned_problem_lookup` 只表示版次兼容，具体习题仍需有可靠的原题文。

课件以 PDF 的实际页序编号，不使用 TeX frame 数或 outline 的序号代替。优先按每页一个文档上传，保证文件引用能映射到确定页码；提取为空或公式明显损坏的页进入质量报告。补充正文按概念或章节切分，数学内容保留 LaTeX。代码按函数和模型切分，并记录关联讲次。

讲次正文的准入条件为 `live`。教材和课程级参考资料按独立登记的身份、版本与阅读范围准入。只按明确清单读取，不递归上传整个仓库或课程包；排除教师讲解、未发布讲次文件、实际考试、学生成绩/作业、教师答案、配置和凭证。普通网页中的共享实验内容按本讲实际渲染结果筛选；历史 syllabus 和旧项目提示不能成为当前课程政策。

服务保存 `file_id → doc_id → 课程位置` 的映射。模型的文件引用通过映射转换成链接；直接放入上下文的当前材料使用服务端生成的来源 ID。链接必须来自这份映射，不能把模型自行生成的 URL 当作有效引用。图像页需要补文字或公式说明；本版不承诺从索引文字完整理解所有图形。

参考文件引用映射到 `reference_id → 版本/章节/页码`；URL 为 null 时仍显示可核验的出处标签。若以后增加受控参考阅读器，再由后端产生经校验的阅读地址。检索上传与直接上下文均只能使用入口检查允许的文档，不能从隔离队列取文本给模型。平台教材依据使用第 6 版选择说明，其他课程政策使用 Fall 2026 syllabus；当前讲的记号与案例遵循课程材料，教材补充推导；习题查找要求实际题文与所问版次一致；成本说明保留报告日期、金额基年和单位。

### 提问上下文与会话

前端发送课程与讲次 ID、语言、当前 section、当前 slide 页码、选中内容和问题。后端根据这些标识从自己的语料读取当前材料，检查讲次发布状态及页码范围。前端提交的选中文字和代码是学生输入，不作为课程权威原文。

上下文优先使用学生选中的内容，其次是明确选择的 slide 或当前概念段落。课件页号用于课件区域的提问；学生正在代码或实验区域提问时，不能默认把课件第 1 页当作问题背景。界面始终显示实际附带的位置，并提供移除或切换。

第一版保留短期会话与有界的最近对话，支持多轮追问。会话由服务端签发，设置过期时间；清除聊天可重新开始。浏览器标识不等同于学生身份。切换讲次后更新当前背景，并提示学生讨论位置已经改变。

短期会话默认 2 小时，最多三轮、12,000 字符历史保存到 D1；每次读取检查有效期，随请求删除过期会话及其请求记录。Pages 另配每 15 分钟运行的清理 Worker，独立 Worker 使用自身 scheduled handler，保证无新请求时也能清理。调用计数和限额由同一 INSERT 与数据库触发器原子检查/更新，避免并发超额；过期清理不退回邀请码和当日额度。模型请求使用 `store: false`，由应用传递近期上下文；这不等同于提供商 Zero Data Retention，上线时说明实际数据处理。

### 接口约定

以下接口已实现，固定字段、SSE 和错误码见 `services/course-chat/README.md`。

| 接口 | 用途 | 关键约定 |
| --- | --- | --- |
| `POST /api/course-chat/session` | 用邀请码建立短期会话 | 返回短期凭证和过期时间；邀请码校验、失败限流均在服务端 |
| `POST /api/course-chat/messages` | 发送问题并接收流式回答 | 携带会话凭证；只接受学生问题与位置，不接受客户端指定模型、系统指令或知识库 ID |
| `GET /api/course-chat/health` | 服务健康检查 | 返回服务状态和语料版本，不泄露凭证或内部文件路径 |

消息请求示例：

```json
{
  "course_id": "ECE685",
  "lecture_id": "L05",
  "language": "zh",
  "context": {
    "kind": "slide",
    "slide_number": 12,
    "section_id": "lecture-overview",
    "selection_text": ""
  },
  "message": "这一页是什么意思？"
}
```

前端使用 `fetch` 读取 SSE 流。后端将提供商事件转换成稳定的应用事件：`start`、`delta`、`sources`、`done`、`error`。只有收到完成事件才将回答标记为完成；流中途失败保留已显示文字并明确标记未完成，避免自动重试造成重复调用。[Responses 流式事件文档](https://developers.openai.com/api/docs/guides/streaming-responses)
